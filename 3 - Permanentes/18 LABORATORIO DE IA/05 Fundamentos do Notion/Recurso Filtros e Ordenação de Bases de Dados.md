# Recurso Filtros e Ordenação de Bases de Dados

## 🎯 Categoria
Recurso

## �� Sumário Executivo
Filtros e ordenação permitem restringir e limitar as informações visíveis em uma base de dados, exibindo apenas o conteúdo relevante, e também organizar a ordem das páginas.

## 📝 Descricao
Filtros e ordenação são mecanismos essenciais no Notion para gerenciar e visualizar dados em bases de dados. Os filtros permitem restringir e limitar o que o usuário quer ver, exibindo apenas conteúdos que atendam a critérios específicos (ex: cliente, fase da estratégia, formato, canal, responsável). A ordenação, por sua vez, permite organizar a sequência das páginas ou itens na base de dados. Este recurso é fundamental para garantir que cada membro da equipe, ou mesmo um cliente externo, visualize somente as informações pertinentes ao seu papel ou às suas necessidades. É considerado o "grande marco" e o "segredo" do Notion devido à sua capacidade de personalizar as visualizações de forma granular, transformando uma única base de dados em múltiplos calendários ou quadros de acordo com as regras aplicadas.

## Complexidade
Intermediario

## ⏱️ Templo de implementação
15-30 min para entender | 1-2 horas para aplicar

## ⚡Como Aplicar
1.  **Acessar Filtros**: Dentro de uma visualização de base de dados, clique em "Filtrar". Pode aparecer um menu rápido com opções ou, para filtros avançados, clique em "Regras".
2.  **Definir Critérios**: Adicione ou edite regras de filtro com base nas propriedades da base de dados (ex: "Cliente é X", "Fase é Y", "Formato é Z", "Responsável é A").
3.  **Aplicar Ordenação**: Na mesma barra de opções da visualização, clique em "Ordenar" e defina a propriedade pela qual deseja organizar os itens (ex: por data de criação, por status).
4.  **Salvar para Todos**: Após configurar os filtros e a ordenação desejados, clique em "Salvar para todos" (botão alaranjado) para que as alterações sejam visíveis a todos os colaboradores. Se não salvar, as mudanças serão vistas apenas pelo usuário que as aplicou.
5.  **Gerenciar Visualizações**: Em calendários e quadros, é possível arrastar itens entre colunas ou faixas para alterar seu status ou fase, o que automaticamente os move para visualizações que correspondam aos novos filtros.
6.  **Criação em Visualizações Filtradas**: Ao criar um novo item diretamente em uma visualização com filtros aplicados, o item já será criado com as propriedades correspondentes aos filtros daquela visualização.

## 💡 Exemplos Práticos
*   Um calendário de conteúdo que exibe apenas itens para um "Cliente X" na "Fase de Estratégia".
*   Um quadro Kanban para designers que mostra apenas tarefas com status "Fazer Design", "Refazer Design" ou "Aprovar Design", agrupadas por fase.
*   Uma visualização de base de dados filtrada por "Criado por" para que cada membro da equipe veja apenas as tarefas pelas quais é responsável.
*   No template Gesto, se uma estratégia nova não aparece, é devido ao filtro de status que não corresponde (ex: status "Em espera" não aparece em visualizações filtradas para "Briefing" ou "Executar").
*   Para controle de acesso de clientes, a base de dados principal é filtrada para que o convidado não veja dados sensíveis ou informações de outros clientes.

## ⚠️ Armadilhas Comuns
*   **Não salvar filtros**: Esquecer de clicar em "Salvar para todos" faz com que as alterações nos filtros não sejam visíveis para outros usuários, gerando confusão e desalinhamento na equipe.
*   **Conteúdo não aparece**: Um item pode não estar visível em uma visualização específica porque seu status ou outras propriedades não atendem aos critérios de filtro configurados para aquela visualização.
*   **Confusão de visualizações**: Mudar a visualização de uma base de dados não significa que os dados foram alterados ou estragados; apenas a forma como são apresentados mudou.

## Consideracoes
Os filtros são essenciais para a segurança e privacidade do cliente, pois controlam o que um convidado pode ver. Novas atualizações do Notion prometem facilitar ainda mais o compartilhamento com limites de acesso mais granulares, sem a necessidade de dar acesso a toda a base de dados.
