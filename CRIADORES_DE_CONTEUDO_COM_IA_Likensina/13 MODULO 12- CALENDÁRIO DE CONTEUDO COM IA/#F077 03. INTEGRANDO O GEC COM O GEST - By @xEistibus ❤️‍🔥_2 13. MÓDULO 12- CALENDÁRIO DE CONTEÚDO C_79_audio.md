O objetivo apresentado é integrar um template de gestão de conteúdo com um template de estratégia. A integração ocorre diretamente na página de estratégia de um cliente específico, permitindo que o calendário de conteúdo fique registrado e mapeado dentro do contexto estratégico daquele cliente, sincronizando-se com o template principal de conteúdo.

## Conexão e Configuração das Bases de Dados

O processo se inicia com a conexão de bases de dados existentes para evitar a duplicação de configurações e informações. A abordagem central é utilizar uma funcionalidade de "vinculação de base de dados", que permite exibir e interagir com dados de qualquer base do sistema dentro da página atual.

### Base de Dados de Clientes

Primeiramente, a base de dados de clientes é conectada à página de estratégia. O objetivo é garantir que o cliente ou projeto em questão esteja disponível para ser vinculado ao conteúdo, sem a necessidade de navegar para outro local do sistema ("outro nojo") para realizar a configuração.

Após vincular a base de dados, que inicialmente exibe todos os clientes cadastrados, um filtro é aplicado para isolar apenas o cliente relevante para a estratégia em questão.

1.  **Filtragem:** É utilizado um "filtro avançado".
2.  **Critério:** A regra é definida para que a propriedade "nome" contenha o nome exato do cliente (no exemplo, "Rafael Weiner").
3.  **Resultado:** A visualização passa a exibir apenas o cliente da estratégia atual, tornando a base de dados indexada a essa informação específica.

Para uma melhor apresentação visual, o layout da visualização é alterado de tabela para "galeria". A configuração do cartão é ajustada para exibir a "capa", garantindo que a foto do cliente apareça de forma "bonitinha".

### Base de Dados de Conteúdo

Em seguida, a base de dados de conteúdo é vinculada à mesma página. A visualização inicial mostra todas as propriedades (colunas) existentes nesta base. O passo seguinte é "limpar" essa visualização, ajustando-a para que suas colunas correspondam exatamente à estrutura de uma tabela que será gerada por uma ferramenta externa, o "GPT de calendário". Isso é feito para que, posteriormente, os dados possam ser simplesmente copiados e colados.

As propriedades que devem ser mantidas na tabela são:
- Título do conteúdo
- Canal
- Formato
- Data da publicação
- Linha editorial
- Etapa do funil
- Tipo de conteúdo (com opções como atração, conexão, conversão e reconversão)
- Ideia

A propriedade "fase" também é mantida por ser considerada útil, enquanto as demais (como "criado por", "links", "responsável" e "cliente") são ocultadas. A propriedade "cliente" é ocultada porque um filtro será aplicado para forçar a associação automática.

Um filtro avançado é configurado para que a propriedade "cliente" seja sempre igual a "Rafael Weiner". Com isso, qualquer novo conteúdo criado a partir desta visualização já será automaticamente relacionado ao cliente correto, eliminando a necessidade de preenchimento manual.

## Organização e Visualização do Conteúdo

Com as bases de dados conectadas e filtradas, o próximo passo é organizar a exibição dos conteúdos de forma funcional.

### Visualizações por Canal

São criadas visualizações distintas para cada canal de conteúdo, como "Instagram" e "YouTube". Isso é feito da seguinte maneira:

1.  Cria-se uma aba (visualização) para cada canal.
2.  Em cada aba, aplica-se uma regra de filtro na propriedade "Canais" para exibir apenas os conteúdos do canal correspondente.

O material explica que, se for necessário adicionar um novo canal que não existe como tag, basta criar a nova tag e, em seguida, uma nova aba filtrando por ela.

### Visualização em Calendário

Para uma visão cronológica, a visualização em tabela é duplicada e seu layout é alterado para "Calendário". Essa visualização também é personalizada:

-   As propriedades exibidas nos cartões do calendário são ajustadas para mostrar a "fase" e a "linha editorial" do conteúdo.
-   Informações já conhecidas pelo contexto da visualização, como o canal e o cliente, são ocultadas dos cartões para manter a exibição limpa.

Adicionalmente, uma regra de ordenação ("sort") é aplicada para que as publicações sejam exibidas em ordem crescente de data, do mais recente para o mais futuro.

O resultado final é uma estrutura organizada, com as informações "tudo bonitinho, tudo prontinho, tudo bem... dentro dos conformes".

## Passo a Passo da Integração

O conteúdo detalha um processo sequencial para realizar a configuração completa.

1.  **Conectar Base de Clientes:** Na página da estratégia, utilizar a "vinculação de base de dados" para adicionar a base de clientes.
2.  **Filtrar Cliente Específico:** Aplicar um filtro avançado para que a visualização mostre apenas o cliente da estratégia atual.
3.  **Personalizar Visualização:** Mudar o layout da visualização do cliente para "galeria" com exibição em "capa".
4.  **Conectar Base de Conteúdo:** Vincular a base de dados de conteúdo à mesma página.
5.  **Ajustar Colunas da Tabela:** Ocultar e reordenar as colunas da tabela de conteúdo para que correspondam à estrutura gerada pelo "GPT de calendário".
6.  **Forçar Associação de Cliente:** Adicionar um filtro para que todo novo conteúdo seja automaticamente vinculado ao cliente da estratégia.
7.  **Criar Abas por Canal:** Criar visualizações filtradas para cada canal de conteúdo (ex: Instagram, YouTube).
8.  **Ordenar por Data:** Aplicar uma ordenação crescente pela data de publicação.
9.  **Criar Visualização de Calendário:** Duplicar a visualização da tabela e alterar seu layout para "calendário".
10. **Configurar Cartões do Calendário:** Personalizar os cartões para exibir as propriedades "fase" e "linha editorial".

## Ferramentas Mencionadas

-   **GPT (GPT de calendário):** Uma ferramenta externa utilizada para gerar uma tabela de calendário de conteúdo. A estrutura criada no sistema principal é modelada para ser idêntica à saída deste GPT, facilitando a transferência de dados.
-   **Ocean:** Mencionado como o sistema onde o calendário será efetivamente gerado. O plano é, em uma próxima etapa, gerar o calendário no Ocean e copiar a tabela resultante para dentro da estrutura recém-configurada.

## Próximos Passos
